## ⭐ TIER 1: ESSENTIAL FOR CREATIVE WRITING (Use Daily)

### 1. **Markdown All in One** (Zhang.markdown-all-in-one)
- **Rank**: #1 - Most Essential
- **Version**: 3.6.2
- **Why You Need It**: You write ALL your blueprints, notes, session summaries, and documentation in Markdown. This extension makes Markdown editing powerful and efficient.
- **How to Activate**: Automatically activates when you open any `.md` file
- **What It Does**: 
  - Provides keyboard shortcuts for Markdown formatting (bold, italic, headers, lists)
  - Auto-completes Markdown syntax
  - Table of contents generation
  - Math formula support
  - Markdown preview with live updates
  - Auto-formatting and cleanup
- **How Helpful**: This is your PRIMARY writing tool. Every blueprint, style guide, session summary, and note file uses Markdown. Without this, you'd be typing raw Markdown syntax manually. It makes your workflow 10x faster. The keyboard shortcuts alone save hours of typing. The table of contents features is perfect for your long blueprint documents.

---

### 2. **Code Spell Checker** (streetsidesoftware.code-spell-checker)
- **Rank**: #2 - Critical for Writing
- **Version**: 4.4.0
- **Why You Need It**: Spell checking is essential for catching typos in your prose, character names, place names, and all your documentation.
- **How to Activate**: Automatically runs on all files (works in Markdown, text files, etc.)
- **What It Does**:
  - Underlines misspelled words with red squiggles
  - Right-click to see suggestions
  - Can add words to custom dictionary (character names, place names like "Sudbury", "WBCN")
  - Works in Markdown, plain text, and code files
  - Supports multiple languages
- **How Helpful**: Essential for your workflow. Catches typos in prose, character names, documentation. You can add custom words (like "Maxanne", "Sudbury", "Aerosmith") to the dictionary so they don't show as errors. Works everywhere - in your blueprints, style guides, chapter files, everything. This is your safety net for spelling errors.

---

### 3. **LTeX+ (Grammar/Spell Checking)** (ltex-plus.vscode-ltex-plus)
- **Rank**: #3 - Advanced Grammar Checking
- **Version**: 15.6.1
- **Why You Need It**: Goes beyond basic spell checking - catches grammar errors, style issues, and writing problems. Perfect for catching "purple prose" patterns and repetitive phrasing.
- **How to Activate**: Automatically activates for Markdown and LaTeX files
- **What It Does**:
  - Advanced grammar checking using LanguageTool
  - Catches grammar mistakes, style issues, wordiness
  - Suggests improvements for clarity
  - Works with Markdown files (your blueprints, notes)
  - Can catch repetitive phrases (like your "frequency" overuse issue)
- **How Helpful**: This is your advanced writing assistant. While Code Spell Checker catches typos, LTeX+ catches grammar mistakes, wordiness, and style issues. It can help identify when you're using the same phrase too often (like "frequency" in Draft 1). It suggests clearer alternatives. Works perfectly with your Markdown files. This is like having a grammar editor built into Cursor.

---

### 4. **Bookmarks** (alefragnani.bookmarks)
- **Rank**: #4 - Navigation Essential
- **Version**: 14.0.0
- **Why You Need It**: Your blueprint documents are LONG (1000+ lines). You need to quickly jump to specific chapters, sections, or notes. Bookmarks let you mark important lines and jump back instantly.
- **How to Activate**: 
  - Keyboard shortcut: `Cmd+Option+K` to toggle bookmark
  - Or use Command Palette: "Bookmarks: Toggle"
- **What It Does**:
  - Mark any line in any file with a bookmark
  - Jump between bookmarks quickly
  - See all bookmarks in sidebar
  - Bookmarks persist across sessions
  - Can label bookmarks with names
- **How Helpful**: Perfect for navigating your massive blueprint documents. Mark Chapter 12 (Dan's Death), Chapter 29 (Battle begins), or specific sections you're working on. Jump instantly between them. No more scrolling through 1000-line documents. This is essential for your workflow - you can mark where you left off, mark sections you need to review, mark important decisions. Saves massive amounts of time.

---

### 5. **Markdownlint** (davidanson.vscode-markdownlint)
- **Rank**: #5 - Markdown Quality
- **Version**: 0.61.1
- **Why You Need It**: Ensures your Markdown files follow best practices. Catches formatting errors, inconsistent heading styles, and Markdown syntax issues. Keeps your documentation clean and professional.
- **How to Activate**: Automatically runs on `.md` files
- **What It Does**:
  - Checks Markdown syntax and formatting
  - Warns about inconsistent heading styles
  - Catches formatting errors
  - Suggests Markdown best practices
  - Shows warnings in Problems panel
- **How Helpful**: Keeps your Markdown files clean and consistent. Catches formatting errors before they become problems. Ensures your blueprints and documentation follow Markdown standards. Helps maintain consistency across all your files. While not as critical as spell checking, it ensures your documentation is professional and error-free.

## ⭐ TIER 2: VERY USEFUL FOR WRITING (Use Regularly)

### 6. **Foam** (foam.foam-vscode)
- **Rank**: #6 - Knowledge Management
- **Version**: 0.29.1
- **Why You Need It**: Creates connections between your documents using wikilinks. Perfect for linking characters, plot points, themes across your blueprints and notes. Creates a knowledge web of your novel.
- **How to Activate**: Automatically activates for Markdown files
- **How to Use**: Type `[[Character Name]]` or `[[Chapter 12]]` to create links between documents
- **What It Does**:
  - Creates wikilinks between Markdown files (like Wikipedia)
  - Shows backlinks (which files link to this one)
  - Graph view of document connections
  - Helps navigate related documents
  - Perfect for linking characters, chapters, themes
- **How Helpful**: Creates a knowledge web of your novel. Link `[[Nick]]` in one document, and it connects to all other documents mentioning Nick. See how characters, themes, and plot points connect across your entire project. The graph view shows the relationships visually. This is powerful for complex novels with multiple protagonists and themes. Helps you see the big picture connections.

---

### 7. **Error Lens** (usernamehw.errorlens)
- **Rank**: #7 - Visual Error Display
- **Version**: 3.26.0
- **Why You Need It**: Shows errors, warnings, and spell check issues directly in the editor (inline), not just in the Problems panel. Makes it easier to see issues as you type.
- **How to Activate**: Automatically activates
- **What It Does**:
  - Shows errors/warnings inline (right in the code/editor)
  - Highlights lines with issues
  - Shows spell check errors inline
  - Displays error messages without opening Problems panel
- **How Helpful**: Makes errors visible immediately. Instead of checking the Problems panel, you see spelling errors and warnings right where you're typing. Saves time and keeps you aware of issues as you write. Especially helpful for catching typos in real-time as you type your prose or documentation.

---

### 8. **Markmap** (gera2ld.markmap-vscode)
- **Rank**: #8 - Visual Organization
- **Version**: 0.2.11
- **Why You Need It**: Creates visual mind maps from your Markdown files. Perfect for visualizing your novel structure, character relationships, or plot arcs. Great for seeing the big picture.
- **How to Activate**: 
  - Command Palette: "Markmap: Create Markmap"
  - Or right-click on Markdown file
- **What It Does**:
  - Converts Markdown headings into visual mind maps
  - Shows hierarchical structure visually
  - Interactive - click to expand/collapse sections
  - Great for visualizing novel structure
- **How Helpful**: Visual representation of your blueprint structure. See your three-act structure, character arcs, and chapter organization as a visual map. Helps you understand the big picture and spot structural issues. Perfect for reviewing your blueprint before printing. Creates a visual overview of your entire novel structure.

## ⭐ TIER 3: USEFUL FOR ORGANIZATION (Use Occasionally)

### 9. **GitLens** (eamodio.gitlens)
- **Rank**: #9 - Version Control Enhancement
- **Version**: 17.9.0
- **Why You Need It**: Enhances Git functionality in Cursor. Shows who changed what, when, and why. Perfect for tracking your writing progress and seeing changes over time.
- **How to Activate**: Automatically activates when Git repository is detected
- **What It Does**:
  - Shows Git blame (who wrote each line, when)
  - File history and change tracking
  - Commit graph visualization
  - Compare versions side-by-side
  - Search commit history
- **How Helpful**: Tracks your writing evolution. See when you made changes, compare different versions of chapters, track your progress over time. Useful for seeing how your prose evolved from Draft 1 to Draft 2. The commit graph shows your writing timeline. Helps you understand your own writing process and track improvements.

---

### 10. **Git Graph** (mhutchie.git-graph)
- **Rank**: #10 - Git Visualization
- **Version**: 1.30.0
- **Why You Need It**: Visual representation of your Git commit history. See your writing timeline, branches (like `draft-2`), and how your novel evolved.
- **How to Activate**: 
  - Command Palette: "Git Graph: View Git Graph"
  - Or click Git Graph icon in Source Control panel
- **What It Does**:
  - Visual graph of Git commits and branches
  - Shows commit history as a tree
  - Click commits to see changes
  - Compare branches visually
- **How Helpful**: Visual timeline of your writing. See your `main` branch (Draft 1) and `draft-2` branch side-by-side. Track when you made major changes, see your writing progress over time. Useful for understanding your own process and seeing the evolution of your novel.

- **How to Activate**: 
  - Command Palette: "Sync Settings: Download Settings"
  - Or "Sync Settings: Upload Settings"
- **What It Does**:
  - Syncs Cursor settings between computers
  - Syncs extension configurations
  - Keeps your setup consistent across machines
- **How Helpful**: Essential for your multi-computer workflow. Keeps your Mac Studio and MacBook Air in sync. Your extensions, settings, and configurations are the same on both machines. Saves time and prevents confusion when switching computers.
