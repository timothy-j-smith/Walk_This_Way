markdown# Core Writing Principles

## Voice & Style

**Active Voice**
- Prefer: "The experiment revealed" 
- Avoid: "It was revealed by the experiment"

**Present Tense for General Truths**
- "Metaphor illuminates code structure"
- Past tense for your specific research: "The data showed"

**First Person When Appropriate**
- "I observed" in qualitative sections
- "We designed" in methodology
- "The results demonstrate" in findings

**Confident Claims**
- "This demonstrates" not "This might suggest"
- Save hedging for genuine uncertainty

## Sentence Structure

**Vary Length**
- Mix short, punchy sentences with longer, flowing ones
- Short for emphasis. Long for explanation and development of complex ideas.

**Strong Verbs**
- "The metaphor illuminates" not "The metaphor is illuminating"
- "Data reveals" not "Data shows that there is"

**Concrete Over Abstract**
- "The cache as library metaphor" not "metaphorical conceptualization"
- Specific examples ground abstract concepts

## Paragraph Structure

**Topic Sentence First**
- Lead with your main point
- Develop and support in subsequent sentences
- Conclude or transition at end

**One Idea Per Paragraph**
- If introducing new idea, start new paragraph
- Use transitions to connect paragraphs

**Evidence → Analysis → Significance**
- Show the data/quote/example
- Explain what it means
- Connect to larger argument

## Transitions

Between paragraphs:
- "This pattern suggests..."
- "Building on this finding..."
- "In contrast to technical naming..."
- "The data reveals an additional dimension..."

Between sections:
- Brief preview at section start
- Brief summary at section end
- Explicit connection to next section

## Clarity

**Define Terms**
- First use: "Temperature (the randomness parameter in AI models)"
- Then use freely

**Explain, Don't Assume**
- Your grandmother should understand the argument
- Technical readers want clarity too

**Examples Illuminate**
- Every abstract claim needs concrete illustration
- Code examples, participant quotes, specific instances

## What to Avoid

❌ Passive voice (unless needed for emphasis)
❌ Hedge words overuse ("possibly," "might," "perhaps")
❌ Jargon without definition
❌ Long paragraphs (break at 150-200 words)
❌ Strings of prepositional phrases
❌ Starting sentences with "There is" or "It is"

## What to Embrace

✅ Specific, concrete details
✅ Active, vivid verbs
✅ Varied sentence rhythm
✅ Your unique voice
✅ Occasional poetic language (when it clarifies!)
✅ Metaphor that illuminates
✅ Confidence in your findings
File: .cursor/rules/manuscript-structure.md
markdown# Manuscript Structure Guidelines

## Chapter/Section Components

### Opening
- **Hook**: Compelling first sentence
- **Context**: What's the landscape?
- **Question**: What are we exploring?
- **Preview**: Where are we going?

### Body
- **Argument development**: Build systematically
- **Evidence**: Data, quotes, examples
- **Analysis**: What does it mean?
- **Counterarguments**: Address alternate explanations

### Closing
- **Synthesis**: Pull threads together
- **Significance**: Why does it matter?
- **Transition**: Bridge to next section

## Document Types

### Academic Paper
Structure: IMRAD (Introduction, Methods, Results, Analysis, Discussion)
- Abstract: 150-250 words
- Introduction: Frame problem + research question
- Methods: Replicable procedures
- Results: Present findings objectively
- Analysis: Interpret findings
- Discussion: Implications, limitations, future work

### Book Chapter
Structure: More flexible, narrative-driven
- Opening narrative or scene
- Develop argument through sections
- Integrate examples throughout
- Synthesize at end with forward motion

### Research Report  
Structure: Practical focus
- Executive summary first
- Context and background
- Methodology brief
- Findings organized by theme
- Actionable recommendations

### Essay/Article
Structure: Argument-driven
- Compelling opening
- Thesis clearly stated
- Development through examples
- Counterarguments addressed
- Strong conclusion

## Section Lengths

**For Book Chapters:**
- Introduction: 500-1000 words
- Main sections: 1500-3000 words each
- Conclusion: 500-1000 words
- Total chapter: 5000-10000 words

**For Papers:**
- Abstract: 150-250 words
- Introduction: 1000-1500 words
- Methods: 1000-1500 words
- Results: 1500-2000 words
- Discussion: 1500-2000 words
- Total: 6000-8000 words

## Navigation

**Signposting**
- Tell them where you're going: "This chapter examines three dimensions..."
- Remind them where you are: "Having established X, we now turn to Y..."
- Show connections: "This finding echoes the pattern observed in Chapter 3..."

**Headings**
- Descriptive, not generic: "Metaphor Density Correlates with Engagement" not "Results 1"
- Parallel structure: All same grammatical form
- Hierarchy clear: H1 > H2 > H3

**Cross-References**
- Forward: "As we'll see in Chapter 5..."
- Backward: "Recall from Chapter 2 that..."
- Internal: "The three factors discussed above..."

javascript// Simple prose linter
export default {
  rules: {
    "passive-voice": {
      check: (text) => {
        const passive = /\b(was|were|is|are|been|being)\s+\w+ed\b/gi;
        const matches = text.match(passive);
        if (matches && matches.length > 5) {
          return {
            pass: false,
            message: `High passive voice usage (${matches.length} instances)`,
            suggestion: "Consider active voice"
          };
        }
        return { pass: true };
      }
    },
    
    "paragraph-length": {
      check: (text) => {
        const paragraphs = text.split('\n\n');
        const long = paragraphs.filter(p => p.split(' ').length > 200);
        if (long.length > 0) {
          return {
            pass: false,
            message: `${long.length} paragraphs exceed 200 words`,
            suggestion: "Break into smaller paragraphs"
          };
        }
        return { pass: true };
      }
    },
    
    "hedge-words": {
      check: (text) => {
        const hedges = /\b(possibly|perhaps|might|maybe|somewhat|fairly|rather)\b/gi;
        const matches = text.match(hedges);
        if (matches && matches.length > 10) {
          return {
            pass: false,
            message: `High hedge word usage (${matches.length} instances)`,
            suggestion: "Be more confident in your claims"
          };
        }
        return { pass: true };
      }
    }
  }
};
